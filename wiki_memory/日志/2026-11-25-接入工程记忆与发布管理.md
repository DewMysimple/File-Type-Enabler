# 接入工程记忆与发布管理

## 目标与范围

用户指定 GitHub 仓库和持续提交推送的交付约定，并要求每个新版本同时提供最新解压目录和按版本命名的 ZIP。

采用 `lite` 工程记忆，根目录 [AGENTS.md](../../AGENTS.md) 提供后续开发入口。当前状态与已有实现以 [状态页](../当前状态/当前状态.md) 为索引。

Codex 将构建与发布脚本放在根构建配置和 `scripts/`，将唯一的生产安装目录与历史 ZIP 集中在 `dist/`。开发监听输出到 Git 忽略的 `.dev/`。选择这一布局以避免开发构建覆盖安装包，并让每个历史版本都可从自己的 ZIP 安装。工程结构见 [README](../../README.md)。

## 验证

2026-11-25 在 Windows 完成记忆初始化预览及应用。初始化前本地尚无 Git 历史，指定 GitHub 仓库为空，默认分支为 `main`。本地已初始化 `main` 并配置 `origin`。

- 首次提交前在 Windows、Node 24.16.0、npm 12.2.3 执行 `npm ci` 和 `npm run build`，类型检查与生产构建通过。执行 `node --check dist/obsidian-file-type-enabler/main.js` 通过。比对 ZIP 三个条目的 SHA-256，均与解压目录对应文件一致。同版本重复构建的产物哈希一致。
- 隔离样本升级到 0.1.1，再构建后解压目录与 0.1.1 ZIP 一致，0.1.0 ZIP 保留原字节。隔离样本中运行 `npm run dev`，修改源码触发发出新开发构建，发布产物保持原字节。
- 模拟新版 ZIP 路径被目录占用。发布失败后恢复安装文件，保留目录额外文件和旧 ZIP。解除占用后重试通过。该验证覆盖可捕获的发布错误。进程被强制终止后，复核 `dist/` 并重建。

## 接续

在工程根目录对照 [交付约定](../../AGENTS.md) 核对本地与远程提交，发布新版本时在检查后提交同版本的两种安装产物。
